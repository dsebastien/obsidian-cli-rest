## Key Decisions

- Desktop-only plugin (requires `child_process`)
- Single HTTP server for both REST and MCP
- Stateless MCP transport (new transport per request)
- POST accepted as universal fallback for all CLI endpoints
- Health and commands endpoints skip auth
- Dangerous commands: eval, restart, devtools, dev:\*, command, reload, plugins:restrict

## Bugs Found and Fixed

1. **Removed `enabled` setting**: Redundant with `autoStart` + toggle command. Server auto-starts on plugin load when `autoStart` is true.
2. **MCP transport incompatibility with Electron**: `StreamableHTTPServerTransport` (Node.js wrapper) uses `@hono/node-server` which is incompatible with Electron's environment. Fixed by switching to `WebStandardStreamableHTTPServerTransport` directly with manual Node.js ↔ Web Standard conversion.
3. **Server orphan on reload**: `onunload()` uses `void this.stopServer()` (not awaited). During rapid reloads, the old server may not release the port before the new one tries to bind. Fixed by: (a) calling `server.closeAllConnections()` before `close()` for immediate port release, (b) not assigning `this.httpServer` until `start()` succeeds (prevents orphaning on failure), (c) adding retry logic with 500ms delay for auto-start.

## Architecture

- REST: `/api/v1/cli/{command}` where `:` becomes `/` in URL
- MCP: `/mcp` using `WebStandardStreamableHTTPServerTransport` (bypasses `@hono/node-server` for Electron compatibility)
- Auth: `Authorization: Bearer <key>` header
- CLI execution: `execFile` for safety (no shell injection)
