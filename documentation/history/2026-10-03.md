# 2026-10-03

## API key moved to Obsidian SecretStorage (issue #13)

**Problem.** The API key sat in plain text in data.json, which travels with the vault (git, Syncthing, cloud).

**Change.** Settings hold `apiKeySecretName` (default `cli-rest-mcp-api-key`); the key lives in `app.secretStorage` and is read at use time (`plugin.getApiKey()`). Logic in `src/app/services/api-key-secret.ts` (pure, tested against `test/memory-secret-store.ts`). Settings row uses `SecretComponent` via `setting.addComponent`.

**Cross-device migration (user requirement: no synced device may need any action).** SecretStorage is device-local, so deleting the plaintext on the first device would lock out the others. The legacy `apiKey` field is kept as a read-only bootstrap: every device copies it into its own SecretStorage on load (and on first read). `legacySecretMigratedAt` records the first migration; the field is purged after 60 days, on Regenerate, on picking another secret, or via "Remove plain-text copy now".

**Decisions.**

- Name collision: never overwrite a different existing secret; use `-2`, `-3`… suffixes.
- Name set, no secret, no legacy copy: persistent Notice + settings hint, server refuses to start (would otherwise run with auth disabled); never regenerate.
- `syncServerAuth` stops a running server if the key became missing instead of pushing an empty (auth-disabling) key.
- Invalid-settings merge now iterates schema keys, so the optional legacy field survives it.
- No logout/clear action: this is a server key, not a session.

**Open.** Needs a live vault check: secret picker row, warning hint, "Remove plain-text copy now" row visibility, migration on a second synced device.
