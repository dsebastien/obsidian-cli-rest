# 2026-06-17

## Fixed issue #3 — Claude Desktop "not valid MCP server configurations"

A Windows user reported Claude Desktop skipping the `obsidian` MCP server with:
_"The following entries in claude_desktop_config.json are not valid MCP server configurations and were skipped: obsidian"_.

**Root cause:** Claude Desktop's `claude_desktop_config.json` only accepts **stdio** servers (`command`/`args`). Our docs documented the `url` + `headers` remote format, which works in Claude Code but is silently rejected by Claude Desktop. No code change — documentation bug.

**Fix (docs only):**

- `docs/mcp-integration.md` — Claude Desktop setup now uses the `mcp-remote` bridge (`npx -y mcp-remote <url> --header Authorization:${AUTH_HEADER}` with the Bearer token passed via the `AUTH_HEADER` env var to dodge mcp-remote's space-in-args bug, which is especially common on Windows). Added a troubleshooting entry matching the exact warning text.
- `README.md` — MCP section now notes Claude Desktop needs the `mcp-remote` bridge and links to the integration guide.

**Note:** the Claude Code config block (`type: url` + `url` + `headers`) is unchanged — that format is valid for Claude Code.
