# 2026-07-17

## Done

- Ported the fixed two-phase release workflow from `obsidian-remarkable-sync` (`.github/workflows/release.yml`, copied verbatim — the old file was byte-identical to the shared original). The old design built and attested artifacts at the triggering commit, then created the version-bump commit and tag, so the build-provenance attestation was bound to a different commit than the release tag and the community-catalog review rejected the release ("attestation failed cryptographic verification").
- New design: a "prepare" job (dispatch on a branch) bumps versions, generates the changelog, commits and lightweight-tags — gated by `bun run build` + `bun test` — then re-dispatches the workflow at the tag ref with `publish=true`; a "publish" job (dispatch-at-tag or bare tag push) builds, attests (`continue-on-error` removed), and creates the release with `github.sha` == tag commit. Design proven live on remarkable-sync 1.5.0 (cert sha == tag commit).
- Updated `scripts/release.sh` workflow description to match the new two-phase flow.
